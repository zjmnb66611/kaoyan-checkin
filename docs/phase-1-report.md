## 关键发现

### 1. 需求全景
- **8 大模块**：任务管理、打卡功能、进度复盘、页面视图、科目体系、设置中心、数据存储、UI规范
- **约 70 条独立需求**，按 P0/P1/P2 三级优先级划分
- **8 项硬性禁令**，明确不可实现的功能范围

### 2. 核心复杂点
- **休息日/请假的任务顺延逻辑**：需要两层优先级（主动顺延 > 被动顺延），且彼此独立
- **周期性任务的自动生成与顺延**：休息日后所有周期任务需同步后移
- **撤销请假的二选一逻辑**：保持顺延 vs 还原日期，影响数据状态
- **双端响应式导航**：移动端底部导航栏 ↔ PC端侧边导航栏
- **离线+云端双存储**：双向同步 + 冲突解决

### 3. 待确认事项（5项）
| 编号 | 问题 | 建议默认值 |
|------|------|-----------|
| Q-01 | 云端存储后端方案 | Supabase (BaaS) |
| Q-02 | 登录方式 | 邮箱+密码 |
| Q-11 | 预置科目可删除性 | 不可删除 |
| Q-16 | 复盘导出功能 | 暂不实现 |

> 其余 11 项问题已有合理默认值，可在开发中直接使用。

## 风险识别

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 任务顺延逻辑复杂 | 容易出 bug | 阶段十一加强单元测试 |
| 离线+云端同步 | 数据一致性挑战 | 明确冲突解决策略（最新时间优先） |
| 需求量大（~70条） | 开发周期长 | P0 优先，分步交付 |
| 移动端+PC双端兼容 | UI 适配工作量大 | 使用响应式设计，减少重复开发 |

## 命名规范约定（供后续阶段使用）

- 文件命名：kebab-case（如 `task-card.js`）
- JS 变量/函数：camelCase（如 `getTaskById()`）
- CSS 类名：kebab-case（如 `.task-card__title`）
- 数据字段：camelCase（如 `scheduledDate`）
- 常量：UPPER_SNAKE_CASE（如 `DEFAULT_EXAM_DATE`）
